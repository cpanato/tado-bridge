# Security policy

This project is pre-1.0. Security fixes target the latest code on `main`; older commits and versions are not maintained as separate release lines. Use the current patched stable Go toolchain and current dependency updates. CI runs race tests, static analysis, module verification and govulncheck; these checks do not replace careful configuration or review.

## Reporting

Use GitHub private vulnerability reporting if it is available for this repository. Otherwise open an issue requesting a private reporting channel without describing the vulnerability publicly. Never include credentials, device codes, API tokens, webhook URLs, account identifiers or raw home/room payloads in an issue, PR, workflow output or attachment.

## Operational boundaries

The bridge only reads upstream data. JSON handlers and metrics read the cache or optional history database and cannot cause tado calls. There are no thermostat controls. Outbound TRMNL publishing requires explicit opt-in; public ingress and external deployments are not automated. A separate release workflow publishes binaries and the GHCR image only after an operator pushes a version tag.

The binary defaults to loopback. A non-loopback bind requires explicit acknowledgement and bearer authentication. The Compose example binds the service to its container interface but publishes the host port only on `127.0.0.1`; API_TOKEN is required. Keep it local or use an operator-managed authenticated proxy/TLS boundary for remote clients. Health/readiness are unauthenticated internal endpoints with generic status only.

Metrics are disabled by default and share the data API's bearer protection when enabled. By default they omit account/home/room identifiers, display names, device serials, token values and error messages. `METRICS_ROOM_DETAILS=true` explicitly opts into cached home/room names and identifier fallbacks for Grafana room discovery, limited to 128 rooms per snapshot. The optional observability Compose overlay enables it; protect Prometheus storage and access accordingly. Tokens and raw errors remain excluded. Aggregate temperatures and humidity are still private climate data. Prometheus may persist them according to its own retention policy.

PostgreSQL history is disabled by default. Enabling it stores full climate snapshots, including private home/room names and IDs, without OAuth credentials. Keep the database private, protect its storage/backups and configure verified TLS for remote connections. The connection URL belongs in a private environment or existing Kubernetes Secret; raw driver errors and passwords are never logged or returned over HTTP. The history endpoint shares API bearer protection and bounds query windows, result counts and payload sizes. Use a separate read-only role for Grafana. Retention defaults to 90 days; the history API excludes expired data, while physical cleanup occurs with the next successful write. Direct SQL readers and backups can retain data longer. See [history operation](docs/history.md).

OAuth credentials are stored unencrypted with owner-only permissions. Mount the containing private directory, not an individual credentials file: token rotation uses same-directory temporary files and atomic rename. The service needs write access to that directory and holds its lock until shutdown. Use one canonical credentials path and do not let another integration rotate the same refresh token. A forced kill may leave a lock; verify no command is running before removing it.

The runtime image defaults to UID/GID 65532, has no shell and includes only the binary, runtime CA/system data and license. Compose drops capabilities, disallows privilege escalation and uses a read-only root filesystem. Only the credentials directory is writable. For bind mounts, run with a matching nonroot host UID/GID; otherwise credential reads/rotation will fail.

The rolling upstream budget is process-local. Restarts and other clients are not included in its history and do not reset tado's account quota. Cache freshness refers to collection time, not proof of a fresh sensor reading. Stale cached data remain accessible; clients must check timestamps/readiness.

Actions are pinned to immutable commit SHAs. The Chainguard base uses `latest`, resolved at build time. Dependabot checks Go modules and Actions weekly with a seven-day version-update cooldown; security updates are not delayed by that cooldown. CI builds containers without pushing them. Container/Compose smoke tests use synthetic credentials with runtime networking disabled. Chart integration uses a disposable Kind cluster, a synthetic HTTPS tado service and a test CA; host aliases route all tado client hosts to the fixture. No application ports are published to the host. Registry login and image publication occur only in the tag-triggered release job, which uses `contents: write` and `packages: write` with the repository token. That job also has `id-token: write` for keyless cosign signing of binaries, checksums and the ko image manifest; it uses the GitHub workflow/tag identity and no stored signing key. There is no automatic tag creation or external deployment workflow. Ordinary CI jobs have no release or registry write permission. The reusable fake and its unauthenticated fixture controls are test-only.

## Optional external consumers

Historical summaries contain private room names/IDs and climate statistics. The summary API shares bearer authentication and database-query bounds with history. Grafana's summary function runs with the caller's database permissions; use the read-only role. Optional native Grafana alerts keep their state in Grafana and are provisioned with an empty receiver and an all-day mute, without replacing notification policies. Enabling external contact points or unmuting those rules is a separate operator action.

TRMNL publishing is disabled by default. Enabling it shares explicitly selected climate readings, display aliases and timestamps with TRMNL cloud. Treat `TRMNL_WEBHOOK_URL` as a bearer secret; it is never included in errors, logs or payloads. Home/zone IDs are used only for local selection. Redirects and HTTP proxy environment variables are disabled for webhook requests, and only official HTTPS private-plugin destinations are accepted. The account/device plugin must be configured manually; no account credentials are needed by the bridge. See [TRMNL setup](integrations/trmnl/README.md).

`TRMNL_HISTORY_SUMMARY` is disabled by default and separately opts into sending selected historical temperature summaries. The projection contains aliases and summary values, not raw home/zone IDs or unselected rooms. Database failures and payload limits do not enable an alternate destination or additional upstream requests.

Local container/snapshot targets use the local ko domain or explicit `--push=false`; an authorized tagged release publishes binaries, native GitHub notes and the application image to `ghcr.io/cpanato/tado-bridge`. The fixture image is snapshot-only and its binary is excluded from signing. CI only runs snapshots with publishing skipped. Helm references preexisting storage and Secrets rather than embedding OAuth/bearer credentials. One replica with Recreate avoids concurrent token rotation during upgrades; neither that setting nor a file lock protects independent copies used by other applications or hosts. See [chart operations](charts/tado-bridge/README.md) before migrating current credentials.
